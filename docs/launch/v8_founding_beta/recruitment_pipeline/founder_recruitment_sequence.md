# Founder recruitment sequence

Australian English. The week-by-week motion for Abdul to fill the 25-person cohort **safely and in warm order**,
at ~3–5 hrs/week. Extends `founder_sales_playbook.md` with the wave-gated timing from `first_25_cohort_plan.md`.
**Nothing is sent by this workstream** — this is the plan Abdul executes, using the variants in
`channel_message_variants.md`.

## Principles
- **Warmest first.** Exhaust internal (network → referrals → SA waitlist) before any community/partner motion.
- **Gate before you grow.** Do not recruit a wave until the prior wave's gate passes (`first_25_cohort_plan.md`).
- **Permission-native.** Every message is invite-only, consent-based, honest, and Spam Act-compliant; honour
  unsubscribe; log prospects with **initials only** (`../command_centre/participant_pipeline_template.csv`).
- **One honest promise.** Manual-entry, no scraping, no live licensed data, not a valuation, not advice.

## Pre-flight (before any outreach)
1. Confirm **Codex technical GO** for the buy-box → deal → Deal Brief journey (this doc doesn't grant it).
2. Confirm invite-only access is ready; brief `../support_playbook.md`.
3. Segment the SA waitlist (SA + actively looking); draft a 5-person Wave-1 target list from Abdul's network.
4. Abdul approves the message variants (`final_launch_approval_packet.md`).

## Week 0 — Wave 1 (5 lighthouse)
| Day | ~time | Action | Variant |
|---|---|---|---|
| Mon | 30 min | Finalise 5 Wave-1 names (most-trusted, most-engaged SA investors) | — |
| Tue | 45 min | Send 5 personal 1:1 invites (warm introduction) | Warm introduction |
| Wed–Thu | 45 min | Onboard responders; watch first buy box + first "bring your own deal" live if possible | — |
| Fri | 30 min | Log activation + first Deal Brief reactions; note any labelling/trust issue | — |

**→ Gate 1 check (end Week 1):** safety + usefulness evidence per `first_25_cohort_plan.md`. If not met, fix and
hold — **do not** open Wave 2.

## Weeks 1–2 — Wave 2 (10) — only if Gate 1 passed
| Day | ~time | Action | Variant |
|---|---|---|---|
| Mon | 30 min | Ask 2–3 delighted Wave-1 users for **one** warm referral each (with permission) | Participant referral request |
| Tue | 60 min | Personal invites to referred SA investors + qualifying SA waitlist opt-ins | Warm introduction / waitlist |
| Thu | 45 min | Seed **one** partner conversation (a trusted broker/accountant) — ask if they'd hand a client the tool | Broker / accountant introduction |
| Ongoing | 30–60 min | Respond within 1 business day; log initials only | Follow-up |

**→ Gate 2 check:** activation tracking to ≥60%, 7-day return to ≥40%, usefulness ≥4.0, no trust regression.

## Weeks 2–3 — Wave 3 (10) — only if Gate 2 passed
| Day | ~time | Action | Variant |
|---|---|---|---|
| Mon | 45 min | Convert partner-referred investors; request **permission-based** SA-local intros (not group posts) | Community-admin permission request |
| Tue | 60 min | If (and only if) a group admin grants permission, post **one** honest, value-first recruitment note | Community recruitment post |
| Wed | 45 min | 2–3 buyer's-agent / educator **research** conversations (learn ICP; not recruitment) | Buyer's-agent research conversation |
| Fri | 30 min | Backfill from waitlist buffer for any decline/no-show | Waitlist / decline response |

## Week 4 — WTP + go/no-go
- Run willingness-to-pay + pricing conversation (`../pricing_research_plan.md`); target ≥40% "yes, at a price".
- Write the go/no-go memo (`../command_centre/go_no_go_scorecard.md`).

## Decline / overflow handling
If demand exceeds a wave's slots, use the **waitlist/decline response** variant — hold people warmly for the next
wave rather than over-filling and overwhelming support. Quality over volume.

## Daily guardrail checklist (every outreach)
- [ ] Consent/opt-in basis for contacting this person is real (network, referral, opted-in, or admin-permitted).
- [ ] Message is honest — no valuation/advice claim, no live-licensed-data claim, no scraping implied.
- [ ] Unsubscribe/opt-out honoured; no bulk/cold blast.
- [ ] Logged with initials only; no personal data in the repo.
