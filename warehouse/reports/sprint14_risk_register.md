# Sprint 14 — Risk Register

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| 1 | Preview and Production share one Supabase project for the main app schema — any future migration applied "for testing" is actually a production change | Ongoing, structural | High | Every migration this sprint requires the same explicit-approval gate used in Sprint 13 WS21; no exceptions, no "just this once." |
| 2 | AI copilot (WS5) scope creep into a real paid model integration | Medium | High (cost, guardrail violation) | Hard rule: use only an already-legitimately-configured provider or a deterministic mock/fallback. `ANTHROPIC_API_KEY` already exists in env for the Strategy Generator — reuse only if genuinely appropriate and cost-bounded; never add a new provider. |
| 3 | Entitlement enforcement (WS12) breaks existing free-tier usage for real users if rolled out incorrectly | Medium | High | Default every existing feature to remain fully available at the `free` tier unless a workstream explicitly and deliberately restricts it; test fixtures for every tier before any enforcement ships. |
| 4 | 26-workstream scope leads to shallow, unverified "coverage theatre" | High if not actively managed | High (violates the brief's own completion criteria) | Explicit tiered prioritization (see execution plan); each shipped workstream fully tested/verified; unreached workstreams documented as such, not silently implied done. |
| 5 | Context/token exhaustion mid-workstream leaves an inconsistent state | Medium | Medium | Checkpoint discipline matching the brief's own instructions: finish or roll back the current atomic change before stopping, never leave a partial migration or ambiguous DB state. |
| 6 | Cursor-tool branches (`cursor/next-steps-process-*`) represent concurrent, unreviewed work on the same repo | Low (not touched) | Low-Medium if ignored indefinitely | Flagged in the baseline report; out of scope for this sprint; recommend the user reviews/prunes them separately. |
| 7 | Rate limiting remains best-effort/single-instance (Sprint 13 gap, still true) | Ongoing | Low-Medium | Documented, not silently carried forward as if fixed; a distributed limiter is new infrastructure requiring approval, out of scope unless explicitly requested. |
| 8 | Watchlist/AI-copilot/refresh-engine workstreams could each independently want a scheduled job | High if unmanaged | High (guardrail: no schedulers without approval) | Every "monitoring"/"digest" feature stays on-demand or dry-run only, exactly as Sprint 13's watchlist change detection was built — no cron, no scheduler, ever, without explicit approval. |
| 9 | Report builder / export surfaces could accumulate CSV-injection risk again as new free-text fields are added | Medium | Medium | Every new export path must reuse `lib/export/csvSafety.ts`, never a fresh unescaped implementation — this was a real bug found and fixed in Sprint 13, must not regress. |
| 10 | Dependency vulnerability set could grow with new packages if WS5/WS11 pull in new libraries carelessly | Medium | Medium | Prefer zero new runtime dependencies; if one is genuinely needed, run `npm audit` before and after and document the delta. |
